---
title: Authorization lifecycle
description: The full path from MCP tools/call to proof receipt or pre-execution denial.
---

Every protected `tools/call` goes through the same boundary.

```mermaid
flowchart TD
    A[Receive tools/call] --> B[Assign configured agent identity]
    B --> C[Normalize tool arguments]
    C --> D[Resolve trusted approval metadata]
    D --> E[Create MidnightAuthorizationRequest]
    E --> F[Run Compact authorization]
    F --> G{Constraints satisfied?}
    G -->|No| H[Return MCP isError]
    H --> I[Do not call upstream tool]
    G -->|Yes| J[Generate and verify proof]
    J --> K[Finalize Midnight transaction]
    K --> L[Call upstream MCP tool]
    L --> M[Attach proof receipt to result metadata]
```

## Fail closed

Malformed requests fail during normalization. Unknown tools still go through Midnight rather than being implicitly allowed. Private policy failures return `policy.AUTHORIZATION_DENIED`, and the upstream MCP handler is never invoked.

## Authorized path

A successful Compact call produces a finalized Midnight transaction and a public receipt. Only after that receipt exists does the gateway forward the original tool call upstream.
